MOCKUP

画面モック

pywebview 内に表示されるフロントエンドの原寸イメージ。実際に操作できます。

このモックは実装前の設計成果物です

アプリは実装済みで、いまの挙動の正は web/ 配下の実装です。実装後に入れた変更（ジャンル・カテゴリの編集ビューと並び替え、ウィンドウサイズの記憶）はモックに反映していません。仕様は詳細設計書を参照してください。

デザインの方針
  • 移植元のレイアウトをそのまま踏襲しています。iOSリマインダー風の単一カラム（上部バー → スマートカード → リスト、詳細はボトムシート）で、カラーパレットも移植元と同じ iOS システムカラーです。
  • ウィンドウの縮小と最大化の両方に対応しました。移植元には @media が1つも無く、狭めると横スクロールが出て操作できず、最大化しても640pxの細い1列のままでした。
  • データはブラウザ内のメモリ上のダミー（js/mock-data.js）。リロードすると初期状態に戻ります。
  • 日付は開いた日を基準に生成されるため、スマートカードの件数がそのまま動きます。
  • CDN・Webフォント・アイコンフォントを使っていません。移植元は Phosphor Icons を unpkg から読んでいましたが、オフラインで動く必要があるためインラインSVGに置き換えました。
  • このモックはブラウザで開いて確認しますが、アプリ本体はブラウザから開けません。HTTPサーバを持たず、pywebview の js_api でPythonを直接呼びます。モックは設計検証用の成果物であって、アプリの機能ではありません。
前回からの変更
  • 最大化時のレイアウトを作りました。1024px以上で3カラムになり、ダッシュボードが常設サイドバー、詳細が右サイドの固定パネルになります（中身は右から滑り込みます）。下からせり上がるのは1023px以下だけです。
  • 絞り込みの日付を「期限の範囲」に変更。「この日以降／以前」の2条件ではなく、開始 〜 終了 の1条件として扱います。チップも1つにまとまり、× で両方外れます。
  • アーカイブを廃止しました。「実行済」で完了タスクを見られるため重複しています（理由は詳細設計書 16章）。
  • 「保留」ステータスを復活させました。移植元は status に保留を持ちながら一覧する手段がなく、切り替えるにも詳細画面を開く必要がありました。スマートカード「保留」に加え、行の末尾（旗の左）に専用トグルを置いています。

操作どこを触るか / 何が起きるか
スマートカード上部のタイル11種。数字が該当件数。タップでそのリストへ
保留済／実行済の表示絞り込みパネルの「ステータス」。既定はどちらもOFFで、一覧には未完了だけが出ます。チェックを入れると、そのステータスだけに絞り「すべて」の一覧へ移ります（件数も連動）。「保留」「実行済」のカードはチェックなしでも中身が出ます
ジャンル絞り込み「ジャンル」の行をタップ。右端の > をタップすると配下カテゴリが開く

保留トグル行右端、旗の左の時計アイコンをタップ。詳細を開かずに保留のオン／オフを切り替えられる。完了中に押すと完了が解けて保留になる
フラグ行右端の旗アイコンをタップ
詳細編集行本文をタップ。狭い時は下からシート、広い時は右サイドパネルに出る。日付行の ⇄ ボタンで期間指定に切り替わる
新規追加右下の ＋ ボタン

絞り込み検索欄の右のスライダーアイコン。ジャンル・カテゴリ・フラグ・期限の範囲で絞る。適用中の条件は一覧の上にチップで出て、× で1つずつ外せる
ジャンル管理上部バー右端の歯車。タスクが残るジャンルは削除を拒否（RESTRICT の挙動）。カテゴリ削除は「なし」になる旨を確認
カレンダー上部バーのカレンダーアイコン。バーにホバーで詳細、クリックでメインへ戻る
