Todoアプリ

Python 3.9 ＋ pywebview ＋ SQLite ｜ ローカル単体で動作するデスクトップアプリ

Ver 1.12026-09-20移植元 C:\Windows11\work\todo_app（Electron + Express + better-sqlite3）
本移植の要点
  • 仕事用ではないため、分類軸を 顧客（customer / project）→ ジャンル（genre） に置き換える。
  • 階層は ジャンル ＞ カテゴリ の2階層。カテゴリはジャンルに従属する。
  • タスクの分類列は文字列保持をやめ、genre_id / category_id の外部キーに正規化する。
  • Electron（Node.js）を廃し、Python + pywebview の単一プロセスに統合する。
  • 画面レイアウトは移植元をそのまま踏襲する。iOSリマインダー風の単一カラム構成とiOSシステムカラー。ただし広いウィンドウでは2〜3カラムへ組み替える。
  • アプリとしてのみ動く。HTTPサーバを持たず、ブラウザから開ける経路を作らない。依存ライブラリは pywebview 1つだけ。
Ver 1.1 の主な変更
  • HTTPサーバ（Flask）を廃止。pywebview の js_api でプロセス内呼び出しにした。ポートもバインドも持たず、ブラウザから開く経路が存在しない（詳細設計書 1章）。
  • アーカイブを廃止。「実行済」と機能が重複しており、2テーブル化の複雑さが移植元で実際にバグを生んでいたため（詳細設計書 16章）。代わりに完了日時を記録する。
  • 「保留」ステータスを一覧できるようにした。移植元は保留を設定できるのに、保留タスクを見る手段が無かった。
  • 絞り込み条件を追加。キーワード・ジャンル・カテゴリ・フラグ・期限の範囲（詳細設計書 10章）。
  • 既定では未完了だけを表示。「保留済のみ」「実行済のみ」のチェックで、そのステータスだけに絞る。終わったものと止まっているものが常に混ざっていると、いま手を付けるものが埋もれるため。
  • レスポンシブ対応。移植元はメディアクエリを1つも持たず、縮めると操作不能・最大化しても640pxのままだった。360pxまで耐え、1024pxで3カラムへ組み替える。詳細が下から出るのは狭い時だけで、広い時は右サイドパネルになる（詳細設計書 11章）。
  • import_log テーブルを廃止。CSVの二重取込は「先にリネームしてから読む」順序で防ぐ。

画面一覧

SCR-01 ダッシュボード

スマートカード11種（遅延／今日／明日／今週／来週／今月／来月／すべて／フラグ付き／保留／実行済）＋ジャンル一覧

SCR-02 タスク一覧

選んだリストのタスク。既定では未完了のみ。適用中の絞り込み条件をチップで表示し、1つずつ外せる

SCR-03 詳細シート

内容・メモ・期限／期間・フラグ・ジャンル・カテゴリ・ステータス。狭い時は下からのシート、1024px以上は右サイドの固定パネル

SCR-04 ジャンル・カテゴリ管理

一覧ビューと編集ビューの2枚。追加・改名・色設定・削除に加え、↑↓ で並び替え。ブラウザのダイアログは使わない

SCR-05 カレンダー

ガントチャート形式。別ウィンドウで開き、一覧と並べて見られる。バーをクリックするとメイン側でその詳細が開く
